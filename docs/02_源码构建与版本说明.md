# 源码构建与版本说明

## 交付版本

本包冻结 2026-10-04 工作区核心代码，以文件哈希为准。根 `SOURCE_SNAPSHOT.json` 保存原始核心文件摘要、Git HEAD 参考值及导出修改清单。它不是原板实时程序快照，不能与原板旧二进制混称同一版本。

交付导出作了这些必要修改：

1. 相机密码和设备所需 MD5 形式从环境读取，缺失即退出；启动脚本读取权限受控的 camera.env。
2. 相机用户名可从环境指定；相机 IP 仍固定为 `.0.123`，雷达仍固定为 `.0.101`。
3. 三个核心程序支持 `XT_DEVICE_SN_FILE`。部署时使用该设备自己的应用身份 YAML，工厂文件保持原样。
4. vizd 的 RTSP/快照 URL 从环境读取；默认不装其运行链路。
5. 导出 shell 脚本统一 LF，加入新板配置模板及标定 OpenCV/NumPy 依赖。

未修改坐标修正、标定求解、业务协议和管理 API 行为。相机凭据外置降低泄漏风险，但凭据可能仍由相机/GStreamer启动参数携带，本次没有完成凭据全链路安全审计。

## Linux / WSL 构建准备

在 Linux 文件系统中构建更快；Windows 可通过 WSL2 使用交付源码。基础工具：aarch64-linux-gnu GCC/G++、CMake、Make、Python3、tar/unzip。下面是 Debian/Ubuntu 安装示例，需网络及管理员权限：

```bash
sudo apt-get update
sudo apt-get install build-essential cmake make gcc-aarch64-linux-gnu g++-aarch64-linux-gnu python3 unzip
```

1. 解包 `dependencies/libzenohc-1.10.0-aarch64-unknown-linux-gnu-debian.zip`。
2. 其中开发包若为 `.deb`，用 `dpkg-deb -x` 解开。
3. 令 `ZENOHC_ROOT` 指向包含 `include/zenoh.h` 和 `lib/libzenohc.a` 的目录。不要把最外层 ZIP 解包目录直接当根目录。
4. 进入 `source`，生成网页内嵌头，再构建：

```bash
python3 scripts/embed_web.py
export ZENOHC_ROOT=/absolute/path/to/zenohc/usr
bash board/build.sh
```

输出 `build/board/xt_camera`、`xt_radar`、`xt_gateway`。此入口会先构建 zenoh-pico 及静态 curl；要求 Zenoh unstable API 和 `FRAG_MAX_SIZE=300000`。默认网关使用 zenoh-c，其余两程序使用 zenoh-pico。不要直接运行旧部署脚本；本包只提供新入口。

`board/build_zenohc_gateway.sh` 当前固定读取项目 `build/curl/lib/libcurl.a`，因此本包重建使用默认 BUILD 路径。若改 BUILD，需同步该脚本路径后复测。

## 可选 vizd 编译

在 `source` 下，核心构建完成后：

```bash
aarch64-linux-gnu-gcc -std=c11 -O2 -static -Ivendor/curl/curl-8.21.0/include vizd/vizd5.c -o build/board/vizd build/curl/lib/libcurl.a -lpthread -ldl -lm
```

运行仍需要 ARM64 FFmpeg；编译成功不证明其网页链路已在新板运行。

## 本轮实际构建边界

本轮对交付快照中的四个应用重新编译并核对 ELF 架构，使用本机已经存在的静态第三方依赖。实际参数、依赖哈希、工具链版本、应用哈希见 `BUILD_RECORD.json`，链接记录见 `build.log`。

这证明应用源码能够用当前工具链链接，**不是完整基础依赖从零重建，也不是第二块 RK3562 实机验收**。静态 glibc 链接包含 getaddrinfo 运行库兼容提示；新板需按同款系统核对 DNS/运行库，而不能只看到 `static` 就认为任意 Linux 均兼容。

安装器还在隔离临时目录中模拟验证了损坏包拒绝、成功安装后的回滚及进程检查失败后的自动恢复；这不能替代真实板端测试。核心 Python 回归与部署脚本检查结果见 `VALIDATION.json`。已存在的旧 Y 轴静态断言失败如实保留，未为了制造“全绿”修改测试。

## 第三方和可选组件

`source/vendor/zenoh-pico`、`source/vendor/json` 保留许可证与声明。curl 原始源码归档随包交付，解开后包含其许可文件。zenoh-c 开发包单独列为依赖，使用方需保存相应版本的上游许可证/源码获取记录。

基础镜像、MPP/GStreamer、Zenoh 路由器、FFmpeg 不属于本包自研代码，需分别确认版本、授权和源码提供要求。包内不附随意从原板复制的第三方运行程序。

蜂鸣器/RTC 目录是选定业务相关源码，未打包音乐素材、Keil 破解材料及其大型重复依赖。其独立构建和引脚适配未在新板核验；本次默认部署不启用。

自研源码交付使用范围、修改权和支持责任以双方合同约定；本包没有为自研代码新增开源授权。
