# 代码目录与数据接口

## 数据链路

```text
MC800S RTSP/H.264 → xt_camera → Unix 图像 ingest socket ┐
                                                       ├→ xt_gateway → zenohd:7447 → PC/甲方程序
XT-M60 TCP控制+UDP距离图 → xt_radar → Unix 点云 socket ┘
```

`xt_gateway` 提供协议命令/配置和 8080 管理 API。`vizd` 是可选 8081 独立预览；它和协议订阅是不同链路。

## SN、主题与格式

示例 `SN=DEVICE00000002`：

| 主题/入口 | 内容 |
|---|---|
| active/SN/image | ImageMsgArray |
| active/SN/pointcloud | LidarPointMsgArray |
| active/SN/cmd/setting | 配置查询/修改，参数空间需区分下述枚举 |
| active/SN/cmd/reboot | 重启命令，仅在授权的设备上使用 |
| active/SN/config_file | 配置文件读取服务 |
| http://设备IP:8080/api/management/status | 运行状态 |
| http://设备IP:8080/api/device | 兼容设备信息 |

`SettingRequest.image_format`：0=保持、1=H.264、2=JPEG。`ImageMsg.format`：3=H.264、2=JPEG。**两个字段的 H.264 数值不同。** config.json 存的是发布格式空间。

JPEG 为 H.264 经 RK MPP 解码/编码得到的 JPEG；不是原生 JPEG 采集承诺。H.264 使用 Annex-B，需另做 AU、IDR/SPS/PPS/GOP 验收。IMU 默认关闭，不输出模拟 IMU。

## 点云坐标与单位

本包包含当前工作区 Y 符号修正：兼容轴为 X 前、Y 左、Z 上。旧板程序与旧标定数据曾使用反向 Y，不能直接复用旧 R/t 或混合采集文件。

坐标值按消息 `header.scaler` 还原，当前常用 scaler=1000。不得把整数坐标直接当米。部署后用已知前/左/右/上/下目标核验方向，再标定该台设备。

雷达点云由距离图和雷达自身内参重建；第三方 SDK 边缘算法存在闭源部分，本实现不能声称与厂商 SDK 逐点完全一致。

## 时间戳

工程模板采用 Unix epoch 微秒。两路当前协议时间戳在处理链路下游产生，不是经过硬件核验的曝光时刻；最近邻差小不能等同于硬件同步误差。跨设备时钟、RTC/NTP 角色和目标同步精度需单独确认。

## 管理端使用边界

当前管理 HTTP 没有完成鉴权改造，监听范围较宽；只在受控隔离联调网络使用，不直接暴露到公共网络。单网口拓扑的网页改 IP 有已知接口选择问题，初次部署用控制台/SSH 明确核对实际网口。
